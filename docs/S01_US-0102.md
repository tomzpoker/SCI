# S01 — US-0102 — Migrations sûres

**Projet :** SCI Family Rust  
**Chemin canonique :** `D:\SCI\DEV\SCI-family-rust`  
**User Story :** US-0102  
**Sprint :** S01 — Socle technique + continuité  
**Dépendance :** US-0101  
**Statut livrable :** `IMPLEMENTED — REVIEW WINDOWS REQUIRED`

## 1. Objectif

Rendre le cycle de migration PostgreSQL reproductible et traçable sans destruction silencieuse.

Le principe retenu est conservateur :

- aucune migration existante n'est réécrite par cette étape ;
- le mécanisme de migration reste celui déjà utilisé par l'application : SQLx ;
- le bootstrap US-0101 ne lance pas les migrations ;
- une sauvegarde est réalisée avant toute migration dynamique ;
- un gate statique bloque les opérations destructives non explicitement approuvées ;
- un rapport horodaté est produit après l'exécution.

## 2. Existant vérifié

L'audit de reprise a identifié cinq migrations :

1. `migrations/0001_foundation.sql`
2. `migrations/0002_onboarding_operations.sql`
3. `migrations/0003_operating_model.sql`
4. `migrations/0004_storage_locations.sql`
5. `migrations/0005_intelligence.sql`

L'existant utilise déjà `sqlx::migrate!("./migrations")` dans `src/infrastructure.rs`.

La revue statique réalisée avant cette livraison n'a pas identifié de `DROP TABLE` ni de `TRUNCATE TABLE` dans ces cinq migrations.

## 3. Politique anti-destructive

Le gate refuse par défaut les constructions suivantes :

- `DROP TABLE`
- `DROP COLUMN`
- `DROP SCHEMA`
- `DROP INDEX`
- `TRUNCATE`
- `DELETE FROM`

Une migration qui doit exceptionnellement en contenir une doit porter explicitement le marqueur :

```sql
-- SCI-DESTRUCTIVE: APPROVED
```

La présence de ce marqueur autorise uniquement le passage du gate statique. Elle ne remplace ni la sauvegarde ni la revue humaine.

Le gate détecte également les doublons de numéros de migration et les noms de migration non conformes.

## 5. Cycle d'exécution

### Gate statique

```powershell
cd D:\SCI\DEV\SCI-family-rust;.\scripts\verify-migrations.ps1
```

### Migration sûre complète

```powershell
cd D:\SCI\DEV\SCI-family-rust;.\scripts\migrate.ps1
```

Le script :

1. vérifie que PostgreSQL du projet est joignable ;
2. exécute le gate statique ;
3. crée `backups\pre-migrate-YYYYMMDD-HHMMSS.sql` ;
4. lance le migrateur Rust ;
5. contrôle `_sqlx_migrations` ;
6. écrit `snapshots\migration-report-YYYYMMDD-HHMMSS.md`.

## 6. Contrats de sécurité

### Pas de suppression silencieuse

Les scripts ne suppriment ni :

- tables métier ;
- colonnes métier ;
- schémas ;
- données utilisateurs ;
- volume PostgreSQL.

### Pas de seed métier automatique

Cette story ne transforme pas les migrations en mécanisme de seed utilisateur.

### Compatibilité avec l'existant

Le moteur métier existant continue d'utiliser SQLx. Il n'y a pas de second framework de migrations.

## 7. Limites volontairement conservées

Cette story ne certifie pas encore :

- la restauration complète d'un backup ;
- les fichiers d'état de continuité ;
- le doctor/recovery complet ;
- la CI/release ;
- les tests de migration sur plusieurs versions historiques et datasets de fixtures.

Ces points appartiennent aux stories suivantes du backlog.
