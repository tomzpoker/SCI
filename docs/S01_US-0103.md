# S01 — US-0103 — Fichiers d’état

**Projet :** SCI Family Rust  
**Chemin canonique :** `D:\SCI\DEV\SCI-family-rust`  
**User Story :** US-0103  
**Sprint :** S01 — Socle technique + continuité  
**Dépendance :** US-0101  
**Statut livrable :** `IMPLEMENTED — REVIEW WINDOWS REQUIRED`

## 1. Objectif

Permettre à un nouveau développeur ou à une nouvelle IA de reprendre le projet sans dépendre de l'historique conversationnel.

Le cahier des charges impose cinq fichiers canoniques :

- `PROJECT_STATE.md`
- `ARCHITECTURE_STATE.md`
- `ROADMAP_STATE.md`
- `DATABASE_STATE.md`
- `VERSION_STATE.md`

Ces fichiers doivent rendre immédiatement lisibles l'état du projet, de la base, de l'architecture, de la roadmap et de la version.

## 2. Fichiers livrés

- `D:\SCI\DEV\SCI-family-rust\PROJECT_STATE.md`
- `D:\SCI\DEV\SCI-family-rust\ARCHITECTURE_STATE.md`
- `D:\SCI\DEV\SCI-family-rust\ROADMAP_STATE.md`
- `D:\SCI\DEV\SCI-family-rust\DATABASE_STATE.md`
- `D:\SCI\DEV\SCI-family-rust\VERSION_STATE.md`
- `D:\SCI\DEV\SCI-family-rust\scripts\update-state.ps1`
- `D:\SCI\DEV\SCI-family-rust\S01_US-0103.md`

## 3. Principe

Les fichiers `.md` sont des documents de continuité versionnables.

Ils ne doivent pas contenir :

- mots de passe ;
- tokens ;
- secrets ;
- données bancaires réelles ;
- documents personnels.

Le script `update-state.ps1` reconstruit les informations volatiles depuis le dépôt local, Cargo et PostgreSQL lorsque celui-ci est disponible.

## 4. Source de vérité

| Information | Source |
|---|---|
| Version projet | `Cargo.toml` |
| Git branch / commit / dirty state | Git local |
| Architecture | fichiers présents sous `src/`, `migrations/`, configuration projet |
| Migrations disponibles | `migrations/*.sql` |
| Migrations appliquées | `_sqlx_migrations` si PostgreSQL est joignable |
| Tests | commandes réellement exécutées / résultat transmis au script |
| Moteurs | `engines/manifest.toml` si présent |
| Roadmap | backlog/cahier des charges + état documenté du dépôt |

## 5. Mise à jour

Commande canonique :

```powershell
cd D:\SCI\DEV\SCI-family-rust;.\scripts\update-state.ps1
```

Option pour écrire explicitement le résultat d'un test :

```powershell
cd D:\SCI\DEV\SCI-family-rust;.\scripts\update-state.ps1 -TestStatus "PASS"
```

Les informations impossibles à vérifier localement sont conservées comme `UNKNOWN` ou `TO_VERIFY`; elles ne sont jamais inventées.

## 6. Git et reprise

Le script tente de mémoriser :

- branche ;
- commit courant ;
- état de travail ;
- remote principal.

Lorsque `.git` n'est pas disponible, le document indique explicitement `NOT_VERIFIED`.

## 7. Base de données

Le script lit :

- le nombre de migrations SQL disponibles ;
- les versions/noms des migrations ;
- `_sqlx_migrations` lorsque PostgreSQL est joignable.

Il distingue donc :

`AVAILABLE` ≠ `APPLIED`

Aucune migration n'est exécutée par `update-state.ps1`.

## 8. Compatibilité avec US-0102

US-0102 reste responsable de l'exécution sûre des migrations.

US-0103 ajoute uniquement la visibilité de leur état.

## 9. Review

Le livrable est conçu pour produire un état exploitable immédiatement après clonage et bootstrap.

**Statut : `READY FOR REVIEW`**

Certification dynamique restante :

1. exécuter `update-state.ps1` sur Windows ;
2. vérifier que les cinq fichiers sont réécrits avec les valeurs locales réelles ;
3. démarrer PostgreSQL pour contrôler `_sqlx_migrations` ;
4. vérifier le cycle `clone → bootstrap → state update → doctor`.
