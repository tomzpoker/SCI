# S01 — US-0105 — Doctor / Recovery

**Projet :** SCI Family Rust  
**Chemin canonique :** `D:\SCI\DEV\SCI-family-rust`  
**User Story :** US-0105  
**Sprint :** S01 — Socle technique + continuité  
**Dépendance :** US-0102  
**Statut livrable :** **IMPLEMENTED — REVIEW WINDOWS/MSVC REQUIRED**

## 1. Référence

Le cahier des charges impose un mécanisme `doctor / recovery` vérifiant DB, migrations, documents, moteurs, configuration et état Git, avec des réparations sûres.

## 2. Design

Le choix est volontairement conservateur :

- `doctor.ps1` est read-only ;
- `recovery.ps1` exige `-Apply` pour modifier quoi que ce soit ;
- aucune suppression de données n'est automatisée ;
- les migrations utilisent exclusivement le runner/gate US-0102 existant ;
- Git est observé mais jamais réécrit ;
- les fichiers d'état ne sont jamais écrasés automatiquement ;
- les secrets `.env` ne sont jamais imprimés.

## 4. Review

Gate statique :

```powershell
cd D:\SCI\DEV\SCI-family-rust;powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-doctor-recovery.ps1
```

Doctor :

```powershell
cd D:\SCI\DEV\SCI-family-rust;powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\doctor.ps1
```

Recovery environnement :

```powershell
cd D:\SCI\DEV\SCI-family-rust;powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\recovery.ps1 -Apply -AllSafeRepairs
```

Recovery + migrations, uniquement après contrôle :

```powershell
cd D:\SCI\DEV\SCI-family-rust;powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\recovery.ps1 -Apply -RepairPostgres -ApplyMigrations
```

## 5. Ship gate

US-0105 ne doit pas être considéré `SHIPPED` avant :

1. gate statique vert ;
2. doctor vert ou avec uniquement des warnings explicites ;
3. scénario PostgreSQL arrêté → recovery → PostgreSQL healthy ;
4. scénario `.env` absent → recovery → `.env` créé sans écraser un `.env` existant ;
5. scénario migrations à appliquer → backup puis migration via US-0102 ;
6. scénario Git dirty → doctor le signale sans modifier le working tree ;
7. vérification qu'aucun chemin GNU/MSYS2 n'est introduit ;
8. rapport de recovery généré.

## 6. Limites

US-0105 ne fait pas :

- restauration complète d'un backup arbitraire ;
- réparation automatique de données métier corrompues ;
- réécriture ou nettoyage Git ;
- inventaire automatique des secrets ;
- synchronisation cloud permanente ;
- réparation silencieuse de fichiers d'état.
