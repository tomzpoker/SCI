# S01 — US-0101 — Bootstrap reproductible

**Projet :** SCI Family Rust  
**Chemin canonique :** `D:\SCI\DEV\SCI-family-rust`  
**User Story :** US-0101  
**Sprint :** S01 — Socle technique + continuité  
**Dépendance :** US-0005  
**Statut livrable :** **IMPLEMENTED — REVIEW WINDOWS REQUIRED**

## 1. Référence

Le cahier des charges maître définit US-0101 ainsi : installer le projet sur un PC vierge ; le bootstrap doit détecter Rust/Git/dépendances/DB, préparer l’environnement et produire un rapport de santé.

Le cycle obligatoire est :

**Research → Design → Plan → Execute → Review → Ship**.

## 2. Research

L’audit US-0005 a établi :

- package Rust déclaré en `0.4.0` ;
- `rust-toolchain.toml` déjà épinglé sur `1.98.1-x86_64-pc-windows-msvc` ;
- cible WASM `wasm32-unknown-unknown` ;
- PostgreSQL 17-alpine sous Docker Compose ;
- `.env.example` avec `DATABASE_URL` ;
- `start.ps1` attend Dioxus CLI 0.7.10 ;
- bootstrap existant trop déclaratif : il vérifie quelques commandes mais ne produit pas de health report et ne vérifie pas les prérequis natifs MSVC ;
- certains scripts voisins injectaient encore `C:\msys64\...` dans `PATH`, ce qui n’est plus compatible avec la décision MSVC.

## 3. Design

Le bootstrap S01 est conçu pour Windows PowerShell et ne dépend d’aucun chemin utilisateur spécifique.

### Pré-requis détectés

1. Rustup
2. Cargo
3. Git
4. toolchain Rust MSVC épinglée par le projet
5. cible WASM
6. composants natifs MSVC / Windows SDK
7. Docker CLI
8. daemon Docker
9. Docker Compose
10. PostgreSQL du projet
11. `.env`
12. migrations
13. manifest des moteurs
14. Dioxus CLI correspondant au lockfile
15. présence du dépôt Git, si le projet a été cloné

### Effets du bootstrap

Le bootstrap :

- ne supprime pas `.env` existant ;
- crée les répertoires nécessaires s’ils sont absents ;
- installe la toolchain Rust MSVC épinglée ;
- installe la cible WASM manquante ;
- démarre uniquement le service PostgreSQL du projet ;
- ne lance pas encore les migrations métier de US-0102 ;
- installe Dioxus CLI si nécessaire ;
- écrit un rapport dans `snapshots/` ;
- retourne un code `0` seulement lorsque les contrôles obligatoires sont verts.

## 5. Execute — modifications livrées

### Remplacement principal

`D:\SCI\DEV\SCI-family-rust\scripts\bootstrap.ps1`

Le nouveau script :

- n’ajoute aucun chemin MSYS2/GNU ;
- vérifie MSVC via Visual Studio Installer / `vswhere` lorsqu’il est disponible ;
- vérifie `vcvars64.bat` et la présence d’un Windows SDK ;
- épingle Rust sur le toolchain du projet ;
- vérifie le target WASM ;
- détecte Docker et lance PostgreSQL avec `docker compose up -d --wait postgres` ;
- teste réellement PostgreSQL avec `pg_isready` dans le conteneur ;
- vérifie Dioxus CLI ;
- produit un rapport de santé sans recopier les secrets du `.env`.

### Cohérence MSVC

Deux scripts voisins doivent également devenir MSVC-neutres afin que la chaîne de diagnostic ne réintroduise pas GNU/MSYS2 :

`D:\SCI\DEV\SCI-family-rust\scripts\doctor.ps1`  
`D:\SCI\DEV\SCI-family-rust\scripts\check-project.ps1`

Cette correction est limitée à la suppression de l’hypothèse MSYS2 et à l’ajout du contrôle MSVC ; l’implémentation complète de recovery reste US-0105.

## 7. Limites volontairement laissées aux stories suivantes

US-0101 ne fait pas :

- l’installation/migration SQL complète ;
- la politique anti-destructive des migrations ;
- la restauration backup ;
- le doctor/recovery complet ;
- les fichiers d’état complets US-0103 ;
- l’observabilité métier US-0104.

## 8. Ship gate

US-0101 ne doit être marqué **SHIPPED** qu’après exécution sur Windows MSVC d’un scénario reproductible couvrant au minimum :

1. environnement sans outils Rust du projet ;
2. lancement de `bootstrap.ps1` ;
3. présence du rapport de santé ;
4. PostgreSQL healthy ;
5. `cargo check --features server` vert ;
6. vérification que le projet n’utilise pas MSYS2/GNU ;
7. état Git proprement identifiable.

Le livrable actuel est donc **READY FOR REVIEW**, pas artificiellement `SHIPPED`.
